# AI 辅助开发实例：博客文章解析

## 项目目标

在 Django 博客文章详情页提供内容解析入口，生成核心观点、内容结构、关键词和阅读建议，并将结果保存到数据库。案例涉及页面请求、后端接口、模型调用和结果展示的完整链路。

## 工具与分工

开发中使用 ChatGPT/GPT 辅助生成代码、解释实现并提供调试建议。我负责提出需求、规划功能，并参与迭代调试、问题定位和 API 使用探索。

后续验收使用 Codex、Playwright 与 Django 测试工具，由 Codex 按验收要求执行并保存证据。本文中的审查结论与运行结果属于本次整理记录，早期具体修改与修复过程仍待补充。

## 技术实现

| 环节 | 实现与代码入口 |
| --- | --- |
| 页面交互 | 文章详情页通过 Fetch 发起 POST，携带 CSRF Token；见 [article_detail.html](../templates/blogapp/article_detail.html) |
| 请求处理 | 登录与请求方法检查，按文章 ID 查询数据；见 [views_chatbot.py](../blogapp/views_chatbot.py) |
| 数据保存 | ArticleAnalysis 与 Article 一对一关联，重复请求读取已有解析；见 [models.py](../blogapp/models.py) |
| 模型接入 | 服务端通过 OpenAI 兼容 SDK 读取模型配置并请求服务；见 [client.py](../blogapp/agent/client.py) |
| 内容处理 | 去除正文 HTML 标签、限制输入长度、构造提示词，对返回文本转义和整理 |
| 响应展示 | JSON 返回 reply 和 cached，页面展示结果 |

```text
点击解析 → POST 业务接口 → 检查登录 → 查询文章与已有解析
  → 有缓存：返回已有结果
  → 无缓存：请求模型 → 整理结果 → 保存数据库 → 返回页面
```

## 代码审查与校验重点

审查围绕以下具体问题展开：

1. 模型密钥是否留在服务端，浏览器请求是否只访问业务接口。
2. 登录限制、CSRF 与请求方法是否符合接口约定。
3. 前端能否处理非成功响应、重定向和缺少 reply 的情况。
4. 修改正文后，已有解析是否仍对应当前内容。
5. 测试是否使用模拟模型，以及真实外部调用是否另有证据。

这些检查需要结合响应、控制台和数据库判断，而不是只观察页面能否打开。本次在异常恢复与缓存更新两处复现问题；尚未实施修复。
